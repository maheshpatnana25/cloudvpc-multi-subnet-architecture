📚 VPC Multi-Subnet Architecture & Viva Preparation Guide

        


        

          

            
1. Problem Definition & Architectural Purpose

            

              In enterprise cloud deployments, hosting web servers, microservices, and databases in a flat network creates severe security risks.
              This project implements a 3-Tier Multi-Subnet Virtual Private Cloud (VPC) spanning 2 Availability Zones (us-east-1a and us-east-1b), strictly decoupling public entry points from sensitive database workloads.
            

          


          

            

              
Tier 1: Public Ingress

              

                Subnets 10.0.1.0/24 & 10.0.2.0/24. Contains the Internet Gateway, Application Load Balancers, Bastion Host, and redundant NAT Gateways. Directly accessible over public internet on ports 80/443.
              

            


            

              
Tier 2: Private Application

              

                Subnets 10.0.10.0/24 & 10.0.20.0/24. No public IP addresses. Contains container & EC2 compute workloads. Outbound internet egress for security patches routes strictly via NAT Gateways.
              

            


            

              
Tier 3: Isolated Database

              

                Subnets 10.0.100.0/24 & 10.0.200.0/24. Strictly isolated route table (no route to 0.0.0.0/0). Security Group restricts ingress strictly to the Application Security Group on port 5432.
              

            

          


          

            
2. Core Networking Concepts & Defense in Depth

            
    
              
  • Stateful Security Groups vs Stateless NACLs: Security Groups track connection state automatically (return traffic allowed regardless of inbound rules). NACLs are stateless and evaluate rules by ascending rule number (100 to 32766), requiring explicit outbound rules for ephemeral port ranges (1024-65535).
    • 
              
  • NAT Gateway vs Internet Gateway: Internet Gateways perform 1:1 NAT for instances with public IPs. NAT Gateways perform Many-to-1 (Source NAT / PAT), allowing private instances to initiate outbound connections while preventing external inbound traffic.
    • 
              
  • AWS 5 Reserved IPs per Subnet: In every subnet, AWS reserves 5 IP addresses: .0 (Network), .1 (VPC Router), .2 (DNS Server), .3 (Reserved for future use), and .255 (Network Broadcast). For a /24 subnet (256 addresses), exactly 251 IPs are usable.
    • 
            

          


          

            
3. Key Viva / Interview Q&A

            

              

                
Q: Why are database subnets not associated with the NAT Gateway route table?

                

                  A: Databases do not need direct access to the public internet. Removing the 0.0.0.0/0 default route guarantees that database clusters cannot leak data to external servers or be exposed to zero-day external network exfiltration.
                

              


              

                
Q: Why deploy NAT Gateways in each Availability Zone instead of sharing one?

                

                  A: Sharing a single NAT Gateway creates an AZ cross-dependency and a single point of failure (if that AZ fails, both AZs lose egress). It also incurs cross-AZ data transfer fees.
